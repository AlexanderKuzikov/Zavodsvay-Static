### 1.1. Яндекс.Метрика

**Обоснование:** поведенческие факторы — ранжирующий фактор Яндекса №1 после
релевантности. Без Метрики нет: данных о bounce rate, глубине просмотра,
конверсиях. Невозможно принимать решения.

**Что делать:**
1. Зарегистрировать счётчик на metrika.yandex.ru для `zavodsvay.ru`
2. Создать цели:
   - `CALL` — клик по `tel:+73422099800`
   - `CALC_OPEN` — посещение `/calc/`
   - `CALC_SUBMIT` — отправка формы калькулятора (если есть)
   - `CONTACT_OPEN` — посещение `/contacts/`
   - `ARTICLE_READ` — скролл >75% на `/articles/*`
3. Включить Вебвизор
4. Создать файл `partials/metrika.php` с кодом счётчика
5. Подключить в `layouts/main.php`, `layouts/home.php`, `layouts/wide.php`
   перед `</body>`

**Файлы:**
- [ ] `partials/metrika.php` — создать
- [ ] `layouts/main.php:45` — добавить `include` перед `</body>`
- [ ] `layouts/home.php` — аналогично
- [ ] `layouts/wide.php` — аналогично

**Критерий готовности:** счётчик виден в исходном коде всех страниц, данные
появляются в интерфейсе Метрики.

### 1.3. robots.txt — убрать Crawl-delay

**Обоснование:** при 570+ URL и crawl-delay 5с полный обход = 47 минут.
Яндекс выделяет ограниченный crawl budget. Задержка искусственно ограничивает
глубину и частоту переиндексации. Для сайта без динамического контента
задержка не нужна.

**Что делать:**
- Удалить строку `Crawl-delay: 5.0` из секции `User-agent: Yandex`

**Файлы:**
- [ ] `robots.txt:12` — удалить строку

**Критерий готовности:** в robots.txt нет Crawl-delay.

### 1.4. meta_description для 28 статей

**Обоснование:** пустой description → Яндекс вырезает сниппет из текста
страницы. Для архаичных статей это будет нечитаемо. Контролируемый description
= контролируемый CTR в выдаче.

**Требования к каждому description:**
- 140–160 символов
- Содержит основной ключ запроса
- Содержит УТП или конкретику (цифры, факты)
- Заканчивается implicit CTA или интригой
- Уникален для каждой статьи

**Шаблон:** `{Ключевой запрос} — {конкретика/УТП}. {Вторичный ключ или CTA}.`

**Обоснование:** единый конверсионный блок в конце каждой статьи. Один файл —

### 2.4. H2/H3 структура для `mashin` и `preimushestva`

**Обоснование:** 2000 слов без единого подзаголовка. Яндекс не может извлечь
структуру. Пользователь не сканирует. Без реструктуризации эти статьи будут
иметь bounce >90%.

**`mashin` — целевая структура:**
```
H1: Машинный монтаж винтовых свай
H2: Когда нужен ямобур, а когда можно вручную
H2: Техника для завинчивания: ямобуры, УБМ, миниэкскаваторы
H2: Производительность и стоимость машинного монтажа
H2: Кабестан: как работает и зачем нужен
```
